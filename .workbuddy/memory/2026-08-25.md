## 任务：Redis 部署 + 12 个疾病库 1000 字文档生成

### 背景
项目原 docker-compose.yml 只有 MySQL 8 + Milvus 向量库（含 etcd/minio），缺 Redis。
用户要求「mysql、redis、向量库」三者齐备部署，并为多个小类生成公开/私有各一篇 1000 字文档。

### 改动清单
1. **docker-compose.yml**
   - 新增 `redis` 服务：`redis:7-alpine`，`--appendonly yes` 持久化，`redis_data` 卷，
     端口 6379，healthcheck（`redis-cli ping`），`${REDIS_PASSWORD:-redis123456}`。
   - `backend` 增加 `depends_on: redis: service_healthy`，并注入
     `REDIS_ENABLE/REDIS_HOST/REDIS_PORT/REDIS_PASSWORD/REDIS_TTL` 环境变量。
   - 顶层 `volumes` 增加 `redis_data`。

2. **后端集成 Redis 缓存**
   - `backend/requirements.txt` 增加 `redis>=5.0.0`。
   - `backend/config.py` 增加 `REDIS_*` 配置（enable/host/port/db/password/ttl）。
   - 新建 `backend/services/cache.py`：Redis 封装，**带进程内内存兜底**——
     Redis 未启用/不可用时自动降级，不阻塞主流程；含 `get_json/set_json/cached_json/clear_prefix`。
   - `backend/services/chat_service.py`：`ask()` 检索结果（rag:hits:）走 `cached_json`，
     相同「问题+可见知识库+公开/私有权限」复用，避免重复向量计算。ChunkHit 均为可序列化标量，缓存安全。

3. **12 个疾病库 1000 字文档**
   - 生成 `backend/data/kb_docs_src/<知识库>/{公开,私有}/*.md`，共 **242 篇**（12 库 × 公开/私有各 10 篇）。
   - 统计：全部 ≥1000 中文字（范围 1000~2695），无缺失小类；对原 uploads 中偏短（<800字）文档补写「日常管理建议」段至约 1000 字，无重复追加。
   - `.gitignore` 加例外 `!backend/data/kb_docs_src/` 与 `!backend/data/kb_docs_src/**`，
     使种子源纳入版本控制、随镜像部署。
   - seed 链路：`KB_DOCS_SRC_DIR = backend/data/kb_docs_src`（`data/kb_docs.py` 定义），
     `seed._seed_disease_kbs()` 遍历 `<知识库>/公开|私有/*.md` 并向量化入库，干净部署即生效。

## 任务：修复「启动后用户输入得不到答案 / vector store empty」

### 现象
后端控制台狂刷 `kb_id=N vector store empty`（每个 kb 两条）；日志开头有 Milvus
`connection params or server unavailable`。检索无结果 → 问答无答案。

### 根因
1. Milvus 连接失败（server unavailable）→ `get_vector_store` 降级到 `NumpyStore` 兜底。
2. 但 NumpyStore 为空：seed 只在 `users` 表为空时跑一次（`_auto_seed` 的 `if count>0: return`）。
   此前首次部署时 `kb_docs_src` 尚不存在（本次才补），`_seed_disease_kbs` 对每个库
   `src_sub` 不存在直接 `continue` → 知识库成空壳、未向量化；MySQL 卷持久化后重部署
   不再 seed → 向量库始终空。
3. 辅助根因：`_add_doc_if_missing` 对已存在但 `status='failed'` 的文档直接 `return`，不重试。

### 修复
- `backend/seed.py` `_add_doc_if_missing`：改为「`status='ready'` 才跳过；不存在或
  `failed/processing` 则清理旧向量后重新向量化」。并复用/回写文档文件。
- `backend/app.py` `_auto_seed`：用户表非空时不再直接 return，而是调用
  `_seed_disease_kbs(cfg)` + `_seed_filler_kbs()` 做**幂等补种**（缺失/失败文档重新向量化）。
  首次仍走 `seed_all` 全量播种。

### 验证
- `py_compile seed.py app.py` 通过；AST 解析通过。
- 逻辑：重部署（users>0）时自动补种知识库文档与向量，向量库非空 → 检索有结果 → 问答有答案。
- embed 在远程 embedding 不可用时有确定性哈希兜底（`llm.py` 已实现），故 Milvus 不可用
  降级 NumpyStore 时仍能把文档向量化（哈希向量语义较弱，但可用）。

### 用户侧生效方式
- 已部署且 MySQL 卷有旧数据：重启 backend 容器（`docker compose restart backend`）即触发补种；
  或镜像重新 build 后 `docker compose up -d --build`。
- 若 Milvus 长期起不来，系统自动用 NumpyStore（纯 Python 向量库）兜底，符合「向量库」部署要求；
  若要用 Milvus，需确保 Milvus 容器资源充足、能正常连接（端口 19530）。
