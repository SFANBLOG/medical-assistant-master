## 任务：修复「启动后用户输入得不到答案 / vector store empty」

### 现象
后端控制台狂刷 `kb_id=N vector store empty`（每个 kb 两条）；日志开头有 Milvus
`connection params or server unavailable`。检索无结果 → 问答无答案。

### 根因
1. Milvus 连接失败（server unavailable）→ `get_vector_store` 降级到 `NumpyStore` 兜底。
2. 但 NumpyStore 为空：seed 只在 `users` 表为空时跑一次（`_auto_seed` 的 `if count>0: return`）。
   此前首次部署时 `kb_docs_src` 尚不存在（本次才补），`_seed_disease_kbs` 对每个库
   `src_sub` 不存在直接 `continue` → 知识库成空壳、未向量化；MySQL 卷持久化后重部署
   不再 seed → 向量库始终空。
3. 辅助根因：`_add_doc_if_missing` 对已存在但 `status='failed'` 的文档直接 `return`，不重试。

### 修复
- `backend/seed.py` `_add_doc_if_missing`：改为「`status='ready'` 才跳过；不存在或
  `failed/processing` 则清理旧向量后重新向量化」。并复用/回写文档文件。
- `backend/app.py` `_auto_seed`：用户表非空时不再直接 return，而是调用
  `_seed_disease_kbs(cfg)` + `_seed_filler_kbs()` 做**幂等补种**（缺失/失败文档重新向量化）。
  首次仍走 `seed_all` 全量播种。

### 验证
- `py_compile seed.py app.py` 通过；AST 解析通过。
- 逻辑：重部署（users>0）时自动补种知识库文档与向量，向量库非空 → 检索有结果 → 问答有答案。
- embed 在远程 embedding 不可用时有确定性哈希兜底（`llm.py` 已实现），故 Milvus 不可用
  降级 NumpyStore 时仍能把文档向量化（哈希向量语义较弱，但可用）。

### 用户侧生效方式
- 已部署且 MySQL 卷有旧数据：重启 backend 容器（`docker compose restart backend`）即触发补种；
  或镜像重新 build 后 `docker compose up -d --build`。
- 若 Milvus 长期起不来，系统自动用 NumpyStore（纯 Python 向量库）兜底，符合「向量库」部署要求；
  若要用 Milvus，需确保 Milvus 容器资源充足、能正常连接（端口 19530）。

## 任务：RAG 全链路改造（用户输入得到杂乱答案 → 优质答案）

### 核心根因（按影响排序）
1. **Embedding 解析缺陷（首要）**：`config._resolve_embed_model` 对 HF 形式 id（如
   `BAAI/bge-base-zh-v1.5`）短路，本地 `backend/data/models/bge-base-zh-v1.5` 完整权重
   **未被加载** → 离线退化成哈希向量 → 语义检索几乎失效 → 答案杂乱。
   且 `_BASE` 定义在 `try: from dotenv import ...` 内，dotenv 缺失时 `_BASE` 未定义会
   `NameError`（已修：提到模块级无条件定义）。
2. **Docker 内模型不挂载**：`.env` 的 `OPENAI_EMBED_MODEL=data/models/...` 是相对路径，
   容器内只挂 `medical_data:/data`，模型目录未挂进容器 → 容器内 embedding 回退哈希。
   已修：`docker-compose.yml` 设 `OPENAI_EMBED_MODEL: /data/models/bge-base-zh-v1.5`
   （environment 优先于 env_file）并挂载 `./backend/data/models:/data/models:ro`。
3. **流式逐 token 删 [n]**：原 `_clean_answer` 在流式时把 `[1][2]` 引用抹掉 → 正文与来源卡片脱钩、
   可能"吃掉"文字。已改为流式**原样下发 [n]**，终稿用 `_clean_for_storage` 仅清理模型自带的
   "参考资料/引用来源"段落，保留 [n]。
4. **无标题切分 / 无去重 / 无重排**：相邻块重叠+跨小节混淆、同文档冗余块喂给 LLM。
5. **提示词弱**：未约束结构、未强制引用与安全边界。

### 改动清单

  绝对路径均可），并打印命中日志；新增 `RERANK_TOP_K/MMR_LAMBDA/MAX_CHUNKS_PER_DOC/
  MAX_CONTEXT_CHARS` RAG 调优参数；`_BASE` 提到模块级。
