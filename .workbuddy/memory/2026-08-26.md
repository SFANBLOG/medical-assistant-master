## RAG 全链路重构（2026-08-26 下午）
用户截图显示 `kb_id=168 vector store empty`，聊天答非所问。根因：
- MySQL `documents` 145 条 `failed`：`file_path` 指向 `内分泌代谢疾病\公开\uuid_xxx.md`（旧 `公开` 目录），真实文件在 `公有\` 且无 uuid 前缀 → `extract_text` 失败。
- 旧 `chunks` 表是更早结构（`is_parent`/`chunk_text`/`tokens`），缺 `parent_id/heading/text/token_count`；`CREATE TABLE IF NOT EXISTS` 不会补列。
- 本地 `sentence_transformers` 加载 bge-base-zh-v1.5 时段错误（Windows + PyTorch 兼容问题），except 无法捕获。
- 根目录 `.env` 仍是 docker compose 配置（`MYSQL_HOST=medical-mysql`、`MILVUS_ENABLE=1`），本地跑 seed 找不到 MySQL/Milvus。

### 修复
1. `backend/models/db.py` 新增 `_ensure_chunk_columns`：幂等为 `chunks` 表添加 `parent_id/heading/text/token_count`；旧列 `chunk_text/is_parent/parent_index` 加默认值/允许 NULL（避免 INSERT 失败）。`init_schema` 同步调用。
2. `backend/services/doc_pipeline.py` 在清理阶段同步 `DELETE FROM sub_chunks/chunk_vectors WHERE doc_id=?`（之前只删 chunks，sub_chunks 旧记录残留导致重复入库）。
3. `backend/services/retriever.py` BM25：`avgdl = float(s["tot"] or 0) / n if n else 0.0`（MySQL `SUM()` 返回 `Decimal`，否则 `float * Decimal` 报错）。
4. 根目录 `.env`：本地开发改回 `MYSQL_HOST=127.0.0.1`、`MILVUS_ENABLE=0`（docker compose 在容器内仍由 `environment:` 覆盖）。`OPENAI_EMBED_MODEL=` 留空走哈希向量兜底。
5. `python seed.py --kb-docs` 成功：630 文档（公开 390 / 私有 240），485 `ready`，11155 子块 + 11155 chunk_vectors，12 个疾病库向量已写入 `data/vectors/kb_172~183.npy`（NumpyStore）。
6. 检索验证：`retrieve(cfg, [176], '痛风主要症状与表现')` 返回 6 个 `ChunkHit`，命中「痛风.md」「痛风性肾病.md」。
