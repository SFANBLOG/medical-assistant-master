# 2026-09-06 工作日志

## 修复：后端启动重复输出（Flask watchdog 反复重启）
- 现象：`python backend/app.py` 控制台把「医智助手·后端启动」横幅 + BGE 模型加载重复打印多遍。
- 根因：`backend/app.py` 的 `app.run(debug=True)` 连带启用 watchdog 文件监视自动重载。Windows 下对目录动静极敏感——用户调试时新建/删除临时脚本（`diag_models.py`、`backend/backend/drop_milvus.py`）、甚至 `.venv/site-packages` 写入都会触发 "Detected change → Restarting" 整服务重启，并偶发 `WinError 10038`。每次重启都重打横幅+重载模型 → 看起来像重复输出。
- 修复（commit `3ca65af`）：
  - `backend/config.py` 新增 `FLASK_DEBUG`（默认 1，保留交互调试器）+ `FLASK_USE_RELOADER`（默认 0，关闭自动重载），均 env 可控。
  - `backend/app.py` `main()` 的 `app.run(debug=config.FLASK_DEBUG, use_reloader=config.FLASK_USE_RELOADER)`。
  - README 环境变量表补两行。
- 验证：`BACKEND_PORT=8099 python -u backend/app.py` 实跑 60s → 横幅 1 次、Restarting 0、正常 Running。⚠️ 直接 `python backend/app.py` 会 `ModuleNotFoundError: backend`（sys.path[0]=backend/），须 `PYTHONPATH=项目根` 或 `python -m backend`（用户 IDE 自带 PYTHONPATH 所以能跑）。
- 注意：用户 8010 老服务（PID 44056，旧代码）需重启才生效。

## ⚠️ git 事故与教训（重要）
- 提交 `3ca65af` 时误把 index 里**遗留的 nginx.conf staged 删除**一起提交了（用户之前工作树删了根 `nginx.conf` 并 stage，未提交）。而 `docker-compose.yml` 的 `frontend.build.context: .` + `Dockerfile.frontend:16 COPY nginx.conf` 依赖根 nginx.conf，删除会导致 docker compose build 失败。
- 已用 `git checkout cf3d55f -- nginx.conf` 恢复并提交 `9b177e2`。
- 教训：**commit 前先 `git status` 看 staged（第一列）内容，勿把用户遗留的 staged 删除/改动卷进自己的提交**；只 `git add` 自己的文件并不能保证 index 里没有用户先前 stage 的条目。
