

# 医智助手 · 医疗知识库智能问答系统

## 项目简介

医智助手是一个面向医院信息系统教学场景的医学知识库智能问答平台，基于 RAG（检索增强生成）技术为用户提供可追溯的医学知识问答服务。系统内置12个疾病知识库，包含公开文档240篇和私有文档240篇，同时提供5种角色门户，为患者、医护与管理人员提供完整的医疗业务功能。

## 技术架构

系统采用前后端分离架构，前端使用Vue 3构建单页应用，后端采用Python Flask提供RESTful API服务。数据存储方面使用MySQL 8作为关系型数据库，Milvus作为向量数据库存储文档向量，支持语义检索功能。

后端服务采用Blueprint + Service分层架构，将路由层、业务逻辑层和数据访问层清晰分离。主要模块包括认证模块（JWT鉴权）、聊天模块（RAG问答）、知识库模块（文档管理）、医疗业务模块（住院、挂号、护理等）和系统管理模块（用户、数据看板）。前端通过Vue Router实现路由管理，使用Pinia进行状态管理，Element Plus作为UI组件库，并集成了ECharts进行数据可视化展示。

## 核心功能

### 智能问答系统

系统支持自然语言医学问答，采用RAG架构实现知识增强生成。用户输入问题后，系统首先进行知识库召回，根据用户角色过滤可见文档，然后构建上下文语境，最后调用大语言模型生成回答。整个过程支持SSE流式响应，前端实时展示回答内容并附带引用来源。系统内置多种向量化模型选择，支持BGE中文语义模型，也提供哈希向量作为离线兜底方案。

### 多角色门户体系

系统严格区分五种用户角色的权限边界。患者角色只能查询公开知识库和公开文档，可查看个人健康档案、预约挂号记录和消费明细。医生角色可以创建和管理知识库，上传公开或私有文档，并查看私有文档内容，同时负责患者管理和住院信息维护。护士角色可以查看患者信息、记录护理内容和查看排班信息。群众角色与患者类似，但不需要关联个人健康数据。管理员拥有最高权限，可管理系统所有用户、全部知识库和数据看板。

### 知识库管理

知识库按照12个疾病系统进行分类，包括呼吸系统疾病、心血管疾病、消化系统疾病、神经系统疾病、内分泌代谢疾病、泌尿肾脏疾病、风湿免疫疾病、感染性疾病、急诊急症、外科骨科疾病、皮肤科疾病和妇儿疾病。每个知识库包含公开和私有两个文件夹，各存放10篇医学文档。文档支持txt、md、pdf、docx和pptx等多种格式上传，系统自动进行文档切分、向量化并存入向量库。

### 医疗业务功能

患者健康档案模块提供住院信息查询、消费明细查询和预约挂号功能。医护工作台提供患者管理、住院信息管理、护理记录录入和排班管理功能。系统管理功能包括用户增删改查和全系统统计看板，支持数据可视化展示。

## 数据库设计

数据库采用MySQL 8，主要数据表包括：users用户表存储用户账号信息；knowledge_bases知识库表记录知识库基础信息及可见性；documents文档表管理上传的文档及其状态；conversations和messages表存储问答会话及消息记录；citations引用来源表记录回答引用的文档片段；hospitalizations住院信息表、bills消费明细表、appointments预约挂号表、nursing_records护理记录表和schedules排班表分别存储各类医疗业务数据。

系统启动时自动创建数据库和所有数据表，并自动播种演示数据，包括五种角色的演示账号、12个疾病知识库的240篇文档以及各业务表的初始化数据。

## 快速部署

### 环境准备

确保系统中已安装MySQL 8数据库，记牢root用户密码。推荐安装Docker和Docker Compose以使用容器化部署方式。

### 配置文件设置

在backend目录或项目根目录创建.env文件，配置数据库连接信息、向量库参数和API密钥。数据库配置包括DB_TYPE、DATABASE_NAME、MYSQL_HOST、MYSQL_PORT、MYSQL_USER和MYSQL_PASSWORD。向量库配置包括MILVUS_ENABLE开关和Milvus连接地址。聊天配置包括OpenAI兼容的API地址、密钥和模型名称，向量化模型推荐使用BAAI/bge-base-zh-v1.5。

### 独立部署

后端部署需要Python 3.11及以上版本。在backend目录下创建虚拟环境并安装依赖包，然后回到项目根目录以包方式启动后端服务。前端部署需要Node 18及以上版本，在frontend目录安装依赖后运行开发服务器或执行生产构建。生产环境建议使用gunicorn启动后端，Nginx托管前端静态资源。

### Docker部署

执行docker compose up --build命令即可完成全部服务的一键启动，包括前端Nginx服务、后端gunicorn服务和MySQL数据库服务。数据持久化存储于Docker卷中。

### 演示账号

系统预置了五个演示账号，密码均为demo123。患者账号patientdemo可查询公开知识库和本人健康档案。医生账号doctordemo可创建管理知识库、上传文档并查看私有文档。护士账号nursedemo可使用护理工作台。群众账号publicdemo可浏览健康资讯和预约挂号。管理员账号admindemo拥有系统管理全部权限。

## 项目结构

项目根目录包含docker-compose.yml用于容器编排，Dockerfile.backend和Dockerfile.frontend分别定义后端和前端镜像构建，nginx.conf配置前端反向代理。backend目录下，app.py是应用入口文件，config.py加载配置参数，requirements.txt列出Python依赖。models目录存放数据库schema定义。routes目录包含各功能模块的API路由定义。services目录实现核心业务逻辑。rag目录实现RAG系统各组件。utils目录提供数据库操作、文件解析、JWT工具等公共功能。frontend目录下，src/views存放各页面组件，src/components存放公共组件，src/api封装HTTP请求，src/router配置路由规则，src/stores使用Pinia进行状态管理。

## 注意事项

系统回答仅用于医疗健康信息辅助理解，不构成诊断、处方或治疗建议，实际医疗问题应咨询专业医生。请勿在配置文件中提交真实账号、数据库密码和API密钥等敏感信息，系统已通过gitignore排除.env文件。
